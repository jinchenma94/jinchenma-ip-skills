# Jinchenma IP 文章插图

## 开始前

先完整读取共同文件，再按当前图片模式读取对应规范：

- `references/ip-pack-format.md`：初始化文章人物配置，导入、激活、切换并解析当前 IP。
- `references/article-workflow.md`：确定图片数量、认知锚点、生成、保存和交付方式。
- `references/illustration-style.md`：解析本次画风与内置人物版本，只加载选中的独立风格包。默认 `jinchenma-3d` 和 3D 人物；旧版需要明确选择。
- 输入包含产品截图，或用户要求把个人 IP 融入截图时，读取 `references/screenshot-ip-mode.md`，保护截图并应用截图 IP 讲解规则。

## 初始化并显示当前 IP

在分析文章前按照 `references/ip-pack-format.md` 完成人物解析：

1. 用户要求导入或切换人物时，先完成相应流程。
2. 第一次运行且没有文章人物配置时，在可交互场景先提示：`当前默认使用 Jinchenma。是否要更换为你自己的 IP 形象？` 用户选择更换时进入人物导入流程；选择不更换时使用内置金尘马。
3. 自定义人物只从文章 Skill 自己的 `ips/` 读取。Builder 包和外部文件只在明确导入时读取并复制。
4. 解析且只加载一个人物 IP 的 `manifest.json`，再加载本次人物版本的三视图和角色规范；同时按画风选择文件解析一个风格包。
5. 开始生图前提示：`当前使用 IP：<displayName> (<ip-id>)；人物版本：<实际版本>；插图画风：<style-id>`。单版本自定义 IP 说明使用现有参考，不虚构 3D 参考资产。

人物身份、人物参考版本、插图画风分别解析。未指定时使用本次默认 3D；截图模式保留原截图，只让当前 IP 延续选定人物版本和画风。

## 执行工作流

1. 读取完整文章、用户提供的全部文字和明确提供的截图。用户提供文章地址时获取完整正文，不根据标题单独推测内容。
2. 提炼核心观点、关键转折、文章情绪和真正值得视觉化的认知锚点，明确每张图要帮助读者理解什么。
3. 根据正文长度和信息密度决定图片数量，合并重复内容，不按章节平均覆盖；基础状态截图能用一句话讲清楚时不选为文章插图。
4. 为每张图选择一种模式：正文内容使用文章插图模式；产品截图、运行结果和界面操作使用截图 IP 讲解模式。不得把两种模式含混地叠在一张图里。
5. 文章插图确定一个核心意思、可见场景/关系和必要物件，按本次风格包完成构图；截图 IP 讲解图锁定必须完整保留的界面区域、指向重点和安全人物位置。
6. 安排当前 IP 的叙事职责、人物尺度、动作和适合当前内容的情绪。
7. 列出少量必须准确呈现的短文字，文章插图的关键文字在正文显示尺寸下应清楚可读；截图中的原有文字、数字、按钮和界面元素全部属于受保护内容。
8. 在内部完成图片方案，不先输出方案，不等待二次确认。
9. 把当前人物 IP 的三视图作为同一角色的多角度参考，逐张独立生成或编辑，不用拼图代替。
10. 逐张检查文章含义、文字准确性与可读性、人物一致性和画面密度；截图模式额外检查界面完整性、指向准确性和关键内容遮挡。每次只修正一个主要问题。
11. 按输出规则保存图片。最终回复保持简短，按顺序列出每张图片、用途、绝对路径和建议插入位置。

## 角色与风格边界

- 共享流程只从当前人物 IP 读取人物身份、服装、配件和稳定色。
- 切换人物只替换角色身份，不隐式选择插图画风；文章分析、数量、保存和交付继续共用同一流程。具体表现只来自选定风格包。
- 将三视图理解为同一角色的正面、侧面、背面，不生成三个角色。
- 让人物参与核心关系，但不要让人物压过文章观点。
- 截图 IP 讲解模式中，让人物像讲解者一样看向或指向截图重点；人物不能遮挡关键按钮、数据、文字、操作路径和已有标注。
- 不重绘、补写或美化截图中的界面，不恢复被裁切、模糊、遮盖或打码的信息。
- 不使用原始真人照片替代人物 IP 内的三视图。
- 不把一次生成中的偶然风格漂移写回人物 IP。

## 输出边界

- 文章插图优先保存到当前项目根目录的 `.jinchenma-assets/<article-slug>/`。
- 无项目、项目不可写或宿主沙箱禁止写入时，回退到 `~/.jinchenma-assets/<article-slug>/`。
- 不覆盖已有图片；使用 `-v2`、`-v3` 递增版本。
- `.jinchenma-assets/` 只保存文章插图，不保存三视图、角色规范或私人 IP。
- 默认把输入文章视为只读，只在最终回复中简要提供每张图片的插入位置。
- 只有用户明确要求把图片引用写入文章时，才修改原文章。
