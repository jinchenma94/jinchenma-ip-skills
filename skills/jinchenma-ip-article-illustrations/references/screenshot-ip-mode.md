# 截图 IP 讲解模式

## 用途

当文章使用产品界面、工作过程、运行结果或对话截图作为插图时，把当前个人 IP 作为讲解者融入截图，形成“老师指着黑板讲解”的画面。截图负责证明真实能力和结果，人物负责建立作者识别和引导视线。

用户明确要求保留原截图时遵循用户要求，不添加人物。用户提供截图并要求突出个人 IP、截图 IP 化或用人物讲解时，默认使用本模式。

## 输入职责

- 原始截图是受保护的编辑目标，也是界面事实来源。
- 当前 IP 本次解析版本的三视图和 `characterSpec` 是人物身份参考；三视图中的三个形象是同一角色的不同角度。
- 文章正文或用户说明负责确定这张截图要证明什么，以及人物应该指向哪里。

不得根据文章描述重新生成一张相似界面来替代原截图。图像工具支持编辑时，必须把原截图作为编辑目标，把当前 IP 三视图作为人物参考。

## 人物职责与位置

- 人物以讲解者身份出现，默认站在左下角或右下角，像老师站在黑板旁边。
- 根据截图空白、次要区域和讲解重点选择左右位置，不固定每张都站同一边。
- 人物朝向截图重点，使用抬手、伸手、指向、侧身讲解或回头示意等清楚动作；手势必须真的指向需要读者看的区域。
- 默认人物约占画布面积的 10%—20%。需要更强个人 IP 时可以适当放大，但仍以不遮挡关键信息为前提。
- 人物可以从画布底边自然出画，形成站在屏幕前讲解的感觉；不要悬浮在界面中央，也不要做成头像贴纸、水印或角标。
- 保持人物包中的脸型、发型、服装、配件、身体比例和稳定配色，不使用真人照片替代三视图。

## 截图保护

- 保留截图的画幅、清晰度、界面结构和原有内容。
- 不修改、重排、重写或伪造截图中的文字、数字、头像、按钮、链接、图标、窗口和运行结果。
- 不遮挡文章需要读者查看的文字、数据、按钮、操作路径、对话内容和已有红框、箭头或重点标记。
- 不恢复被裁切、模糊、遮盖或打码的信息，也不根据上下文猜测缺失内容。
- 原截图已经包含明确标注时优先利用原标注，让人物指向它；不要再堆一套重复的箭头、红框和说明文字。
- 原截图没有安全放置人物的区域时，依次选择更小人物、切换左右角或适度扩展画布留白。仍会遮挡关键信息时，保留原截图并说明无法安全加入人物，不强行合成。

## 视觉关系

- 截图继续保持产品界面的原始视觉，不套用超现实背景、漫画滤镜或统一重绘。
- 只有个人 IP 角色采用本次选定画风与人物身份色：默认柔和 3D；明确旧版时使用低饱和彩色漫画和轻手绘轮廓。人物与真实截图形成编辑式组合，原截图不随人物画风改变。
- 可以增加一条克制的指向线或极轻阴影帮助人物落在画面里；已有标注足够时不要新增。
- 不增加与讲解无关的装饰、气泡、标题、表情包、贴纸、边框和营销元素。
- 不把多张截图拼成一张长拼图；每张高价值截图独立处理和交付。

## 选择截图

- 优先使用能够证明关键能力、操作位置、真实结果或多人协作关系的截图。
- 账号已出现、页面能打开、按钮存在等一句话就能讲清楚的基础状态通常不配图。
- 一张截图能同时证明岗位设置与首次结果、任务安排与运行结果等多个相关信息时，优先保留这一张。
- 截图数量由文章需要决定，不按步骤平均配图，也不为了突出 IP 重复使用相似画面。

## 生成提示必须包含

1. 明确说明第一张输入图是必须保护的截图编辑目标。
2. 明确说明第二张输入图是同一人物的正面、侧面和背面三视图。
3. 写清人物站在左下角还是右下角、朝向哪里、使用什么讲解动作。
4. 写清人物应指向的具体界面区域，以及不得遮挡的关键内容。
5. 要求截图中的文字、数字、按钮、窗口、标注和布局保持原样。
6. 要求人物延续当前 IP 身份和本次选定画风，禁止生成真人、头像贴纸、水印和第二个角色。

## 检查

- 截图中的关键文字、数字、按钮、窗口和原有标注是否保持准确、清晰、完整。
- 人物是否与当前 IP 的三视图和角色规范一致。
- 人物是否像讲解者一样参与画面，而不是装饰性贴纸。
- 指向动作是否准确，视线是否引导到文章真正要讲的区域。
- 人物是否避开关键信息，大小是否足以建立 IP 识别但没有压过截图。
- 是否没有重绘界面、编造数据、恢复隐私信息、重复标注或增加无关装饰。
